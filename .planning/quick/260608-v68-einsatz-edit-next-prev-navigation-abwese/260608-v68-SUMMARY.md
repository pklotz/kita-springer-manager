## What Was Built

### Task 1 — Prev/Next Navigation (9577b79)

`AssignmentView.vue` erweitert um:
- `siblings` ref: alle Einsätze ohne `status='free'` via `assignmentsApi.list()`, sortiert nach Datum/Startzeit (Backend liefert bereits `ORDER BY a.date, a.start_time`)
- Computed `currentIndex`, `prevId`, `nextId`
- `goToSibling(id)` → `router.push('/assignments/' + id)`
- `watch(() => route.params.id, ...)` lädt Einsatz + Verbindungen bei Param-Wechsel neu
- ChevronLeft/ChevronRight-Buttons mit `disabled:opacity-50` an den Rändern
- Bestehender ArrowLeft-Button (zurück zum Kalender) unverändert

### Task 2 — Backend Batch Endpoint (ebb88b5)

**`internal/store/closures.go`:**
- `ClosureAssignmentConflicts(db, dates)`: findet scheduled Einsätze an den Closure-Daten; nutzt `assignmentSelect`+`scanAssignments` aus demselben Package
- `CreateClosuresBatch(db, closures)`: `BEGIN`/`INSERT OR IGNORE` pro Closure/`COMMIT`; defer tx.Rollback(); Fehler mit fmt.Errorf gewrappt

**`internal/api/handlers/closures.go`:**
- `CreateClosuresBatch`: decodeJSON (unbekannte Felder abgelehnt), Validierung (type, date_from, date_to, note, max 366 Tage), Konfliktprüfung nur für `springerin` ohne `force`, 409 mit strukturiertem Body (`error` + `conflicts`), 201 `{created: N}`

**`internal/api/router.go`:**
- `r.Post("/batch", h.CreateClosuresBatch)` in `/closures`-Route ergänzt

### Task 3 — Frontend Batch + Rückfrage (226c8cc)

**`frontend/src/api/index.js`:**
- `closuresApi.createBatch(data)` ergänzt (POST /closures/batch)

**`frontend/src/components/ClosureForm.vue`:**
- Tag-für-Tag-Schleife ersetzt durch einen `createBatch`-Aufruf
- 409-Catch: `confirm()` mit Backend-Meldung; bei Bestätigung `createBatch({ ...payload, force: true })`; bei Abbrechen stilles return (kein Toast)
- Nicht-409-Fehler: weiterwerfen → globaler Interceptor zeigt Toast
- dayjs-Import entfernt (nicht mehr benötigt)
